# Portfolio design and implementation review

Reviewed 13 September 2026. Direction: a professional, transportation-engineering-first portfolio for an early-career Civil Engineer at Stantec.

| Finding | Implemented response |
| --- | --- |
| Body copy and labels were frequently 11–13px; tightly spaced headings made the page feel compressed. | Established 16px body copy, a consistent metadata scale, more moderate heading tracking, and roomier paragraph and card spacing. Kept self-hosted Manrope. |
| The visual system had overlapping responsive overrides and cramped phone controls. | Reorganized responsive rules, retained the navy/blue palette, enlarged header controls to 44px, and corrected phone portrait/title placement. |
| Filters covered only eight projects; fourteen further assignments were difficult to discover. | Search and categories now cover all 22 assignments. Matching additional assignments expand automatically; clear and empty states explain the result. |
| Overview project links led to broad sections rather than the work being shown. | Featured cards identify Chiquita Boulevard and DRAFE. Added stable project anchors that reveal contribution details and place keyboard focus on the project heading. |
| Navigation reset the visitor's reading position and the heading structure skipped levels. | Added reading-position restoration for Back/Forward, de-duplicated history events, and gave each focused view a primary heading. Retained the mobile keyboard focus trap. |
| Resume and credits screen typography differed from the main site. | Improved their screen readability and moved their CSS into local stylesheets. Preserved the resume's print rules and content. |

## Content and engineering decisions

All substantive experience, project, education, research, leadership, and service paragraphs are preserved. The public resume body is unchanged. Professional identity remains Civil Engineer at Stantec; credentials are not inferred from job title. Project copy describes individual contributions within a team; the DRAFE study remains explicitly a coauthored preprint.

The supplied headshot, real credited illustrative photography, seven-section navigation, background signal sequence, and interactive traffic demonstration remain. No framework or new runtime dependency was introduced. Core eager references are approximately 85 KiB compressed, excluding lazy photographs and alternate image sizes; this is a source-based transfer estimate, not a measured loading-time score.

## Verification

- Static checks: local files, fragments, accessibility references, CSP, privacy rules, image metadata, photography attribution, all 22 assignments, and stable featured-project anchors.
- All seven sections tested at 320px with no horizontal overflow; overview inspected at 390px, tablet at 768px, desktop at the app's normal width; 1440px layout dimensions checked.
- Project search tested against an additional assignment (MOSI), category filtering, an empty result, clear search, and a featured-project deep link after an incompatible filter.
- Mobile drawer opening/closing, keyboard focus trap, Escape focus return, page-heading focus, and Back navigation restoring the reading position tested.
- Dark/light themes, global motion pause, simulation demand/speed controls, and local sequence pause tested. Existing reduced-motion handling was retained and reviewed in source.
- Resume and photo-credits screen layouts inspected at 320px without horizontal overflow; print-specific CSS and resume content are unchanged. Fresh PDF pagination was not measured in this pass.
- No browser console warnings or errors were observed during local QA.
